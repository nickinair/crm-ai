## 一、当前代码基线（开工前的事实）

| 模块 | 现状 |
|---|---|
| 订单后端 | `order` 模块已存在，但只有 3 个接口（列表、按客户查、创建），无状态流转、无详情 |
| 订单实体 | `biz_order` 缺：平台订单编号、三方订单编号、车辆快照、客户快照、作废原因、创建人/更新人；`biz_order_item` 缺商品编码快照 |
| 订单前端 | `Order.tsx`、`OrderAddModal.tsx` 为早期脚手架，非三步式，需重做 |
| 商品 | `biz_product` 缺商品属性、商品备注；适用车型/安装属性目前非字典驱动；列表无筛选、无批量导入 |
| 账号 | `sys_account` 无外呼账号字段 |
| 线索 | 无「线索创建类型」「分配管控标识」「订单情况」字段；无锁定表；无冷却期定时任务 |
| 操作日志 | `sys_operation_log` 表存在但未使用（0 行） |
| 线索状态 | 现有状态 7「战败已被领取」——**本次需求要求去掉**，改用「分配管控标识」机制 |

## 二、任务拆解（共 18 个任务，5 个阶段）

每个任务= 一次可独立部署验证的交付单元。标注 **[依赖]** 的必须等前置任务完成。

### 阶段一：数据底座（必须最先做，其余全部依赖）

**T1 — 数据字典扩充**（PRD 4.7）
- 新增字典类型：下单平台、营销活动名称、品牌、车型、款式、适用车型、安装属性、商品属性、战败线索冷却期（单位：天）
- 商品属性按商品类型分组取值（整车延保 → 交付之日起90天内 / 交付之日起91天~45个月；电池延保 → 交付45个月且9.5万公里内 / 24个月内且4万公里）
- 需支持「按父级值过滤子选项」的字典查询能力（现有字典接口不支持，需扩展）

**T2 — 数据库结构升级**（一次性 DDL，避免后续反复改表）**[依赖 T1]**
- `biz_order` 扩字段：平台订单编号、三方订单编号、作废原因、创建人、更新人、客户快照（姓名/手机号）、车辆快照（品牌/车型/VIN）、关联线索编码
- `biz_order_item` 扩字段：商品编码快照
- `biz_product` 扩字段：商品属性、商品备注
- `sys_account` 扩字段：关联外呼账号、关联外呼账号密码
- `biz_lead` 扩字段：线索创建类型（普通新建/战败线索复活）、分配管控标识（战败冷却期/战败已复活）、订单情况（未下单/存在未完结订单/全部订单已作废/全部订单已完结）
- 新建 `biz_lead_lock` 表：线索编码、销售编码、锁定时间、解锁时间、浏览器会话标识
- 启用 `sys_operation_log`：操作类型、操作人、操作时间、操作内容（字段名：变更前 → 变更后）

### 阶段二：商品模块（相对独立，可最快见效）

**T3 — 商品列表筛选 + 字段扩展**（4.5.1 / 4.5.3）**[依赖 T1、T2]**
- 列表增加筛选：商品名称（模糊）、商品编码、商品类型、商品属性、状态、创建时间区间
- 列表增加「商品属性」「商品备注」列，备注 hover 展示全文
- 新增/编辑弹框：适用车型、安装属性、成本价改为**非必填**；适用车型、安装属性改字典驱动；增加商品属性（随商品类型联动）、商品备注

**T4 — 商品批量导入**（4.5.2）**[依赖 T3]**
- 两步式弹框：下载模板 → 上传文件
- 文件校验：非空、表头匹配、仅 .xlsx/.xls、5M 以内
- 数据校验：必填未填、字段超长、商品编码/名称唯一性、表内重复（提示重复行号）、枚举值不匹配
- 导入结果：总数/成功数/失败数 + 刷新列表；失败 > 0 时可下载错误文件（原表头 + 红色错误信息列）
- 可复用现有线索导入的批量预取 + 分块插入方案（500 行/批）

### 阶段三：订单核心（本期最大模块）

**T5 — 订单后端 API**（4.2.2 / 4.2.3）**[依赖 T2]**
- 状态机：待发送电子签 → 待签署电子签 → 待三方下单 → 待发货 → 已完结；任意非终态可作废
- 接口：创建（草稿→正式）、列表（多条件筛选+分页+排序）、详情、状态流转、录入三方订单编号、作废（带原因）
- 提交订单时保存快照：商品（编码/名称/售价）、车辆（品牌/车型/VIN）、客户（姓名/手机号）、线索编码
- 权限：仅订单跟进人具备操作权限

**T6 — 订单管理页面**（4.2.3）**[依赖 T5]**
- 列表字段：订单编号、客户姓名、客户电话、下单平台、平台订单编号、三方订单编号、车架号、订单状态、实付金额、跟进人、创建时间、创建人、更新时间、更新人
- 各状态操作：非终态「详情/作废」，已完结/已作废仅「详情」；作废单展示作废原因
- 订单详情页（新路由）；关联线索可跳转线索详情，无关联显示「-」

**T7 — 三步式创建订单弹框**（4.2.3.2）**[依赖 T5]**
- 第一步 客户信息：选择系统客户（手机号/姓名搜索）或新增客户（手机号唯一性校验后直接落库）
- 第二步 订单+商品：下单平台、平台订单编号（30字符）、实付金额（数字10字符）、商品（仅「正常」状态可选）→ 存草稿
- 第三步 车辆信息：下拉展示「车型（车架号）_车牌」拼接（空字段跳过，全空显示"未获取到车辆展示信息"）；支持新增车辆（草稿）；**商品含电池延保/整车延保时车辆必填**并红字提醒
- 提交校验：① 同车辆存在未完结订单且商品重叠 → 二次确认；② 客户存在未完结线索 → 询问是否绑定线索
- 提交成功：草稿转正式（订单/车辆），车辆关联客户，新客户创建私域关系；取消则删除订单与车辆草稿（客户保留）

**T8 — 销售工作台「我的跟单订单」**（4.2.3.1）**[依赖 T5、T7]**
- 新增 tab，仅展示跟进人=当前登录人的订单；按状态（多选）+ 客户手机号筛选；创建时间倒序，支持创建/更新时间排序
- 状态操作按钮：已发送电子签 / 已签署电子签 / 录入三方订单编号 / 已完成发货 / 作废 / 详情，各带二次确认文案
- 「已完成发货」分支：订单未绑线索 → 直接完结；绑定线索 → 提示"完结订单将一并完结线索"
- 快捷工具栏增加「新增线索」「创建订单」按钮

**T9 — 订单与线索联动**（4.2.4.1 + 各状态流转的跟进记录）**[依赖 T5、T8]**
- 每次状态变更且订单绑定线索时，自动写入一条跟进记录（操作人=系统），文案按 PRD 逐条对应
- 线索「订单情况」字段随订单状态自动重算（无订单→未下单；有未完结→存在未完结订单；全作废→全部订单已作废；全完结→全部订单已完结）

### 阶段四：线索模块改造

**T10 — 新增线索改为三步式**（4.3.3 / 4.2.3.3 / 4.2.5.2）**[依赖 T1]**
- 三步：客户信息 → 车辆信息 → 商品信息；新增客户/车辆在「下一步」时即落库并建立关联
- 三个入口统一：线索池管理、销售工作台快捷工具栏（保存后自动分配给当前销售）、客户360（客户信息锁定不可改）

**T11 — 线索池管理列表改造**（4.3.1）**[依赖 T2]**
- 去掉「战败已领取」状态（回退我此前实现的状态 7，改用分配管控标识）
- 新增列：线索创建类型（创建时间前）、订单情况（关联订单编号前）、分配管控标识（线索状态前）；操作列固定
- 新增筛选：订单情况、线索创建类型、分配管控标识
- 操作列按「状态 × 分配管控标识」矩阵控制；存在分配管控标识时不可分配/领取
- 关联订单编号多个换行展示，可跳转订单详情

**T12 — 线索锁定机制**（4.3.1）**[依赖 T2、T11]**
- 进入线索详情建锁，关闭释放；session 过期自动解锁
- 重新分配前判锁：已锁定的不可重新分配

**T13 — 重新分配 + 冷却期定时任务 + 历史数据刷数**（4.3.1 / 4.3.2 / 4.8）**[依赖 T11、T12]**
- 「重新分配」单条 + 批量：仅待跟进/跟进中可操作，含状态校验提示、锁定失败明细提示
- 二次确认「线索关联未完结订单是否一并重新分配？」（默认是）→ 同步改订单跟进人
- 战败线索领取/分配：原线索不变，copy 新线索（创建类型=战败线索复活），父线索标记=战败已复活
- 每日 0 点定时任务：按「最新更新时间 + 冷却期天数」对比当天，设置或清空分配管控标识
- 历史数据刷数脚本：无父线索→普通新建；有父线索→战败线索复活；原状态 7 → 分配管控标识=战败已复活

**T14 — 线索详情改造**（4.3.3）**[依赖 T2、T9]**
- 展示线索创建类型、分配管控标识、订单情况
- 战败复活线索：跟进记录合并展示所有父级线索记录 + 当前记录，按时间倒序
- 增加「历史订单」列表（可跳详情）、「操作日志」（倒序分页 10 条/页，滚动加载）
- 跟进记录弹框去掉「已完成」状态选项

## 五、风险与工作量提示

- **本期体量很大**：18 个任务里订单模块（T5~T9）几乎是从零重做，加上线索池改造（T11~T13）涉及分配/领取核心逻辑，改动面广、回归风险高。建议按阶段分批上生产，而不是攒一个大版本。
- **线索池核心逻辑改动**需重点回归：分配、领取、退回公域池、战败克隆——这几处近期刚修过多个线上问题。
- **锁定机制（T12）**依赖会话标识与超时释放，异常场景（浏览器崩溃、断网）需兜底，否则会出现线索被永久锁死。
- 所有任务完成后需要一次完整回归，建议在测试环境用生产样本数据跑。

## 六、⚠️ 生产发布前必读

**本期后端代码已依赖新表结构，直接部署到生产会报错。**

生产发布前必须先在生产库执行迁移（顺序不可颠倒）：

```bash
DB_HOST=<生产库地址> DB_PORT=<端口> DB_USERNAME=root DB_PASSWORD=<密码> DB_DATABASE=crm_sales \
  node docs/migrations/V1.1.0-T2-schema.js --dry-run   # 先看将执行什么
```

确认无误后去掉 `--dry-run` 执行，然后依次执行 `V1.1.0-T1-dict.js`、`V1.1.0-T3-product-data.js`、`V1.1.0-T13-backfill.js`（历史数据刷数：状态7迁移+创建类型+冷却标识），最后才 `./deploy.sh all`。
四个脚本都是幂等的，重复执行安全。
